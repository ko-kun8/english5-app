# Task7-1D 同名ユーザー対応

## 目的

現在のユーザー管理を、

「表示名」と「内部ユーザーID（UUID）」を完全に分離する。

同じ名前のユーザーが複数存在しても、
それぞれ別ユーザーとして扱い、学習データを絶対に混在させない。

---

# 最重要ルール

## ① 表示名は重複OK

例：

かおる
かおる

この状態を許可する。

「同じ名前だから登録できない」という仕様にはしない。

---

## ② ユーザーの識別は必ずUUIDで行う

例：

かおる
→ user_id = 3d970397-02e4-4b4a-9323-df4ed40690bf

かおる
→ user_id = 8xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

名前ではユーザーを識別しない。

必ず user_id / UUID を内部識別子として使用する。

---

## ③ 同名ユーザー登録時も新しいUUIDを発行

新規ユーザー登録で「かおる」と入力された場合、

既存の「かおる」を検索して再利用してはいけない。

必ず新しいUUIDを1回だけ生成する。

例：

既存
かおる → UUID-A

新規登録
かおる → UUID-B

として完全に別ユーザーにする。

---

# データ構造

users/

├ UUID-A/
│  └ user_data.json
│
├ UUID-B/
│  └ user_data.json

例：

users/
├ 3d970397-02e4-4b4a-9323-df4ed40690bf/
│  └ user_data.json
│
└ 8xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx/
   └ user_data.json

user_data.jsonには少なくとも

- user_id
- display_name
- 学習履歴
- レベル
- Coin
- バッジ
- その他現在のユーザー固有データ

を保持する。

---

# ④ 名前によるデータ検索・上書きを禁止

以下のような処理が存在する場合は修正する。

NG：

- display_name == "かおる" でユーザーを検索してデータを取得
- 名前が同じなら既存ユーザーを再利用
- 名前をキーにして学習履歴を保存
- 名前をキーにしてCoinやLvを保存
- 同名ユーザーを統合する
- 同名ユーザーの片方を削除する

OK：

user_id → ユーザーデータ

という関係で管理する。

---

# ⑤ 現在の自動増殖防止を絶対に壊さない

Task7-1Cで修正した、

- 旧フォルダの移行済み判定
- `.migrated`
- 既存UUIDの再利用
- マイグレーション時の重複UUID生成防止
- 新規登録時のみUUIDを発行

の仕組みを維持する。

今回のTask7-1Dで、
旧データのマイグレーション処理を不用意に変更しない。

特に、

「同名ユーザーが存在する」
という理由だけでUUIDを新規生成する処理を追加してはいけない。

UUID生成は、

1. 本当に新規ユーザー登録ボタンを押した場合
2. 必要な旧データの初回移行

だけに限定する。

---

# ⑥ ユーザー選択画面

同名ユーザーが存在する場合でも両方表示する。

例：

👦 かおる
🐱 かおる
👧 はなこ

など。

同名ユーザーでも、それぞれ別ボタンとして表示する。

ボタンの内部keyも必ずUUIDを使用する。

例：

key=f"user_select_btn_{user_id}"

---

# ⑦ 同名ユーザーを見分けられるUI

同じ名前のユーザーが複数いる場合、
ユーザー選択画面で区別できるようにする。

現在のアプリにアバター・アイコン選択機能がある場合は、
それを利用して同名ユーザーでも見分けやすくする。

例：

🐱 かおる
🐶 かおる

既存UIを大きく変更する必要はない。

まずは「同名でも別ユーザーとして正常に選択できること」を優先する。

---

# ⑧ ユーザー切替

ユーザーAからユーザーBへ切り替えた場合、

- current_user
- user_id
- learning_history
- learned_words
- not_learned_words
- level
- Coin
- badges
- shop購入情報
- daily mission
- その他ユーザー固有session_state

をユーザーBのデータに正しく切り替える。

ユーザーAのデータをユーザーBへ引き継がない。

---

# ⑨ 新規同名ユーザーの初期状態

既存の「かおる」がLv.3でも、

新しく「かおる」を登録した場合、

新しい「かおる」は必ず

Lv.1
覚えた単語 0
苦手単語 0
学習数 0
正答率 0%
Coin 0
バッジ未取得

から開始する。

既存の「かおる」のデータをコピーしない。

# 重要

今回のTaskでは、

- ユーザー認証
- パスワード
- メールアドレス
- ログイン機能
- Streamlit Cloud向け本格認証

は実装しない。

今回はあくまで、

「表示名は重複可能」
「UUIDでユーザーを完全に識別」
「ユーザーデータを完全分離」

までを実装する。

---

# 既存機能を壊さない

以下を必ず維持する。

- 4択クイズ
- 通常モード
- 苦手復習
- 効果音
- レベルアップ
- Coin
- デイリーミッション
- バッジ
- ショップ
- 学習履歴
- ユーザー切替

既存機能にエラーが発生した場合は、
同名ユーザー対応だけでなく、その原因も修正する。
