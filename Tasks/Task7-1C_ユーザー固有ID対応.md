# Task7-1C_ユーザー固有ID対応

## 目的

Task7-1A・Task7-1Bで実装したユーザー管理を拡張し、

「表示名」と「ユーザーを識別する固有ID」を完全に分離する。

名前だけでユーザーを識別すると、
同じ名前の利用者が存在した場合にデータが混ざる可能性がある。

そのため、ユーザー作成時に自動的に固有IDを発行する。

---

# 重要な方針

今回のTaskでは、

「認証機能」は実装しない。

Googleログイン、Appleログイン、
メールアドレス・パスワードなども実装しない。

今回はあくまで、

表示名
↓
ユーザー固有ID
↓
個人データ

という構造を作る。

将来APP化するときに、
Google / Apple / メール認証などと接続できる構造にする。

---

# 現在の問題

現在は、

ユーザー名
↓
ユーザー識別

となっている。

例えば、

たろう
↓
users/taro/

となっている。

この方式では、

Aさん「たろう」

Bさん「たろう」

が存在した場合、
同じユーザーとして扱われる可能性がある。

---

# 新しい仕様

ユーザー作成時に自動で固有IDを生成する。

例：

表示名：

たろう

ユーザーID：

a8f3c91e

保存：

users/
└ a8f3c91e/
    └ user_data.json
    └ learning_history.json

別の利用者が同じ「たろう」という名前で登録した場合、

表示名：

たろう

ユーザーID：

72bd51f4

保存：

users/
└ 72bd51f4/
    └ user_data.json
    └ learning_history.json

とする。

---

# ユーザーID

ユーザーIDは自動生成する。

ユーザーが入力する必要はない。

UUIDなど、
十分に重複しない方式を使用する。

例：

xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx

または短縮表示用ID。

重要なのは、

「名前が同じでもユーザーIDが必ず違う」

ことである。

---

# 表示名

名前はあくまで画面表示用。

例：

👤 たろう

ユーザー識別には名前を使用しない。

---

# 保存構造

推奨：

users/
├ <user_id_1>/
│   ├ user_data.json
│   └ learning_history.json
│
├ <user_id_2>/
│   ├ user_data.json
│   └ learning_history.json
│
└ <user_id_3>/
    ├ user_data.json
    └ learning_history.json

既存のユーザー別学習履歴の仕組みを壊さず、
ユーザー名ベースからユーザーIDベースへ変更する。

---

# user_data.json

ユーザー基本情報を保存する。

例：

{
    "user_id": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
    "display_name": "たろう"
}

必要に応じて現在のユーザー情報を追加してよい。

---

# learning_history.json

これまで通り学習履歴を保存する。

ただし保存場所を、

users/<user_id>/learning_history.json

とする。

---

# player_data.json

既存のplayer_data.jsonがユーザー共通データとして扱われている場合は、
ユーザー固有データとの関係を確認する。

Coin、EXP、レベル、バッジ、ショップ購入情報など、
ユーザーごとに保存すべきデータが共通ファイルに残らないようにする。

ただし、現在のアプリ構造を確認せずに
大幅なデータ構造変更を行わない。

必要な変更のみ行う。

---

# 現在のユーザー管理

Task7-1Bで実装した、

・ユーザー選択
・新規ユーザー
・ユーザー切替
・current_user
・reset_user_session()
・set_active_user()

を確認する。

これらを壊さない。

current_userには、
可能であればユーザー名ではなくuser_idを保持する。

表示するときだけdisplay_nameを取得する。

---

# ユーザー切替

ユーザー切替時は、

user_id

を基準にユーザーを切り替える。

名前を基準にしない。

例：

たろう（user_id A）

から

たろう（user_id B）

へ切り替えられる。

---

# 新規ユーザー

新規ユーザー作成時：

1. 表示名を入力

2. 新しいuser_idを自動生成

3. users/<user_id>/を作成

4. user_data.jsonを作成

5. learning_history.jsonを初期状態で作成

6. Lv.1から開始

---

# 新規ユーザー初期状態

・覚えた単語 0

・苦手単語 0

・学習数 0

・正解数 0

・不正解数 0

・正答率 0%

・レベル 1

・EXP 0

・Coin 0

・バッジ未取得

・ショップ購入なし

既存ユーザーのデータをコピーしない。

---

# 既存ユーザー

Task7-1A・Task7-1Bで作成済みのユーザーについては、
既存データを勝手に削除しない。

既存ユーザーを新しいuser_id構造へ移行する必要がある場合は、
必ず現在のデータ構造を確認してから移行する。

既存データを上書き・削除する場合は、
バックアップを作成する。

---

# 同名ユーザーテスト

名前「たろう」

ユーザーB：

名前「たろう」

結果：

・別々のuser_idになる

・別々のCoinになる
・別々のバッジになる
・別々のショップ購入情報になる

ことを確認する。
